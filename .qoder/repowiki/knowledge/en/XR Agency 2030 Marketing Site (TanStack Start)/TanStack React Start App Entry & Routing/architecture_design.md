The module is organized around TanStack React Start's convention-based architecture. `src/server.ts` exports a Cloudflare Workers-style `fetch` handler that lazily imports `@tanstack/react-start/server-entry`, wraps the resulting response with an `normalizeCatastrophicSsrResponse` guard that detects h3-swallowed SSR errors (JSON bodies with `{unhandled:true,message:'HTTPError'}`) and returns a rendered HTML error page via `renderErrorPage`. `src/start.ts` builds the Start instance with two request-level middlewares: an error middleware that catches non-`statusCode` errors and renders the same HTML error page, and a CSRF middleware scoped to `serverFn` handlers — explicitly re-added because defining `start.ts` opts out of the default CSRF protection. `src/router.tsx` creates a single `QueryClient` per router instance and wires it into the router context via `createRouter({ routeTree, context: { queryClient } })`. `src/routeTree.gen.ts` is auto-generated by TanStack Router from the `src/routes/` directory tree, mapping file paths to typed route objects (`/` → `index.tsx`, `/services/$serviceId` → `services/$serviceId.tsx`) and augmenting the framework's `Register` interface so TypeScript knows the `router` and `ssr` types. The `routes/` folder holds the actual page components: `__root.tsx` defines the root route with `<html>`/`<head>`/`<body>` shell, global meta tags, SEO/OpenGraph/Twitter metadata, a `NotFoundComponent`, an `ErrorComponent` that reports via `reportLovableError`, and a `RootComponent` that providers `QueryClientProvider` and `LanguageProvider` around an `<Outlet />`; `index.tsx` is the landing page; `services/$serviceId.tsx` is a parameterized route using a `loader` to fetch service data and `notFound()` for missing IDs.
